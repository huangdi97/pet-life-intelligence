# PLI R8AE · 主人来源核对界面：可阅读的证据卡片

## 来自真实 Android 截图的问题

最新已验收工程 HEAD `a62ad4a0` 的 `r5-6-android-runtime-evidence` 中，`android/r8-owner-review/raw-sources.png` 展示 12 条原始记录的统一白底灰色长文本列表。全部真实来源与双时间虽然都能读到，但“记录数值 / 发生时间 / 录入时间 / 身份 ID”没有清晰的扫描层级，尤其在手机长列表内阅读困难。

## 本次源实现

- 证据进度独立一行；当日依据和同期参考是并排、自动换行的轻量标签，数量只代表已实际展开的记录。
- 当日依据使用克制的鼠尾草绿色背景，历史同期记录使用浅燕麦暖色背景；每条来源成为独立的信息卡片，并保持轻量留白。
- **每一条**仍由同一个 React Native Text 组件承载完整事实、两个时间、来源身份、8 字符视觉 ID 和无障碍中的完整不可变 ID，因此不降低 11/12 条真实 UIAutomator 来源证据门槛。
- 继续保留每页最多 8 条、宠物 ID 校验、双时态事实、主人决定和禁止推断疾病等原有机制。
- 完整辅助测试只检查代码语义和真实 helper；新布局在当前提交完成 CI 和 Android 运行截图之前 **不能**称为视觉验收或已经符合参考设计。

不使用视觉模型对截图进行验收。 `NO_VISION_MODEL_USED=TRUE` · `HUMAN_VISUAL_ACCEPTANCE=PENDING`. 不修改已批准视觉基线、不合并、不打标签、不发布正式版本。
